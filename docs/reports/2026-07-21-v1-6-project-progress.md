# Sort Manager v1.6 项目进度与后续路线

## 2. 后端模块进度

### 2.1 账号、安全与家庭边界

- 已完成 OWNER/MEMBER 角色、JWT 短访问令牌、一次性刷新令牌轮换、登录失败限流和账号启停。
- 所有业务数据都通过当前家庭 ID 约束，OWNER 专属运营接口同时受 URL 规则和方法授权保护。
- OWNER 可撤销指定成员的全部刷新会话；停用成员时自动撤销其会话。
- 文件访问需要认证，上传包含类型、扩展名、大小和路径安全校验。
- 后续缺口：过期刷新令牌的定期清理、全家庭“一键撤销其他设备”、登录设备说明和安全事件提醒。

### 2.2 物品、分类与位置

- 已完成物品新增、编辑、移动、分页搜索、状态筛选、图片、批量移动和批量删除。
- v1.6 将物品删除改为家庭范围内的软删除；普通列表、统计和搜索统一排除回收站数据。
- OWNER 可分页查看回收站、恢复或永久删除；永久删除不可恢复且需要二次确认。
- 分类和位置列表使用一次数据库聚合获取物品数，不再逐项计数。
- 分类或位置仍被普通/回收站物品引用时禁止删除并返回明确提示；有子位置时也禁止直接删除。
- 后续缺口：回收站自动保留期、批量恢复/清空、物品变更历史详情、附件多图和图片压缩去重。

### 2.3 批量录入

- 支持最多 100 行 CSV/Excel/WPS 粘贴内容的预检与原子提交。
- 服务端统一校验名称、数量、价格、日期、分类和位置；任一行无效时整批不落库。
- 审计记录整批录入动作，避免为每行生成高噪声事件。
- 后续缺口：直接上传 `.xlsx`、可下载错误报告、图片批量关联、扫码/OCR 辅助录入和重复物品提示。

### 2.4 统计看板

- 已完成物品、分类、位置、未分类、总资产、近期物品、临期物品和分布统计。
- v1.6 将总资产、临期列表、分类/位置分布改为数据库聚合和有界查询，移除了全量物品载入与 N+1 查找。
- 后续缺口：统计时间趋势、库存变化、家庭成员贡献、可配置临期阈值和统计导出。

### 2.5 家庭运营与审计

- 关键物品、批量录入、成员启停和会话撤销操作记录为只追加审计事件。
- OWNER 可按动作筛选、分页查看“运行纸带”，并看到 7 天操作数、成员数、活动会话和回收站数量。
- 审计写入与业务变更使用同一事务，避免“业务成功但审计缺失”。
- 后续缺口：审计导出/归档、保留策略、IP/客户端信息、重要事件通知；若未来有更强防篡改要求，再考虑哈希链或外部只写日志存储。

## 3. 前端模块进度

### 3.1 PC Web

- React 19 + Vite 7 的页面包含登录、看板、物品、批量录入、位置、分类、成员和家庭运营。
- PC 端支持完整管理操作；移动宽度下提供底部导航，并从看板的“家庭数据保护”入口进入 OWNER 运营页。

- 后续缺口：统一表单组件、更多页面级错误恢复、虚拟列表/图片懒加载、无障碍自动扫描和前端错误上报。

### 3.2 微信小程序

- 原生小程序已覆盖登录与 Token 刷新、家庭总览、分页搜索、单件快速录入、个人页和退出。
- OWNER 个人页读取家庭保护摘要；MEMBER 不请求受保护接口；四 Tab 结构保持简洁。
- 后续最有价值的是扫码快速定位/录入、图片拍摄压缩、完整物品编辑、回收站入口、下拉刷新体验和开发者工具 UI 自动化。
- 微信一键登录不是当前家庭私有部署的前置条件；只有在账号绑定体验成为明显痛点时再引入。

## 4. 数据保护与部署进度

- `ops/backup.ps1` 将 MySQL dump 与上传目录打包，使用 PBKDF2-SHA256（210,000 次）、AES-256-CBC 和 HMAC-SHA256 先加密后认证。
- 清单记录每个文件的大小和 SHA-256；恢复脚本先认证再解密，并拒绝路径穿越、重复/未声明文件和源数据库覆盖。
- 恢复默认为只验证；显式应用时必须指定不同的隔离数据库和新建/空上传目录。
- 后端只读取不含秘密的有界状态 JSON，不接触口令、归档或恢复权限。
- 已用本机真实 MySQL 8 数据库完成加密备份和只验证恢复演练。
- 部署前仍必须完成：专用最小权限备份账号、任务计划、异机/异盘复制、保留周期、失败告警、`APP_BACKUP_STATUS_PATH`、HTTPS 反向代理和至少季度一次隔离恢复演练。

## 5. 技术架构判断

当前架构适合家庭私有应用，无需更换：

- 单体 Spring Boot 对单家庭、低并发、事务一致性和备份恢复最简单可靠。
- React Web + 原生微信小程序可以共享稳定 JSON API，同时分别获得 PC 管理效率和手机原生体验。
- MySQL + Flyway 适合结构化物品、家庭关系和可审计升级；当前没有引入事件溯源或微服务的收益。
- 环境变量、同源 HTTPS 反向代理和文件/数据库持久卷足以支持自有服务器部署。

建议只做渐进式结构调整：后端代码继续按 `auth / inventory / household / operations` 领域收拢，前端逐步提取表单、分页和状态组件；在单体内保持清晰边界。只有出现多个家庭租户、大量并发、独立团队或外部集成平台时，才重新评估服务拆分。

## 6. 后续优先级

### P0：先把 v1.6 真正运营起来

1. 在服务器配置每天加密备份、至少 7 个日备份和 4 个周备份，并复制到不同物理设备或对象存储。
2. 配置备份状态路径与失败告警，使用独立最小权限数据库账号；完成一次隔离数据库和上传目录的真实恢复演练。
3. 部署 HTTPS 反向代理、精确 CORS、日志轮转、磁盘空间监控和 MySQL 仅内网访问。

### P1：建议作为 v1.7“高效录入与数据可携带”

1. CSV/Excel 导出、`.xlsx` 导入和错误报告下载，确保家庭数据随时可迁移。
2. 小程序扫码搜索/快速录入，配合相机拍照压缩；这是日常使用频率最高的效率提升。
3. 回收站批量恢复/清理、默认 30 天保留策略和即将自动清理提示。
4. 过期刷新令牌清理、设备会话列表和“一键退出其他设备”。

### P2：体验和可观测性

1. 小程序补齐编辑、移动、回收站和开发者工具 UI 自动化。
2. 备份、登录失败、磁盘不足和服务不可用通知；增加结构化日志和基础指标。
3. 图片缩略图、懒加载、去重与过期孤儿文件清理。
4. 看板趋势、临期阈值设置、家庭周报和统计导出。

### P3：有明确需求后再做

- 微信一键登录、OCR/AI 自动识别、离线写入冲突合并、多家庭切换、事件流或微服务拆分。
- 这些能力会显著增加账号绑定、同步、隐私或运维复杂度，目前不应抢占数据可恢复和高频录入工作的优先级。
