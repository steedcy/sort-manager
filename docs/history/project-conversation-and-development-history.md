## 4. MySQL 自动联调与管理员恢复

### 4.1 自动连接检查

根据用户要求，系统自动检查了：

- `MySQL80` 服务状态。
- 无密码 root 登录。
- README 旧默认密码登录。
- `mysql_config_editor` 登录路径。
- MySQL Workbench 本地连接记录。

检查结果是服务运行正常，但没有可复用的有效凭据。系统没有在未授权情况下重置密码，而是请求用户明确授权。

### 4.2 root 密码重置

用户明确授权后，执行了本机 MySQL 管理员恢复流程：

1. 短暂停止 `MySQL80`。
2. 以本机权限恢复模式启动 MySQL。
3. 重置 root 密码。
4. 终止恢复进程并恢复正常服务。
5. 通过 TCP 验证 root 登录。

第一次恢复探针因为 PowerShell 将 MySQL stderr 警告解释为异常而中止。此时密码尚未修改，保护逻辑成功恢复了正常 MySQL 服务。调整原生命令错误处理后，第二次恢复成功。

真实密码仅保存在 Git 忽略的本机文件中，并通过 ACL 限制为当前 Windows 用户访问。

## 6. v1.2 项目进度评估

v1.2 被评估为可正常使用的个人物品管理 MVP：

- 核心业务完成度约 85%。
- 前后端工程质量约 65%。
- 安全与生产准备约 40%。

主要缺口：

- 没有登录、鉴权和权限隔离。

由此确定 v1.3 应优先解决安全与可靠性，而不是继续扩展业务功能。

- 空数据库执行 V1、V2。

- Flyway baseline 1 成功。

### 7.5 示例数据脚本编码事件

## 10. 目标技术架构

建议保留统一后端，不为 PC 和小程序分别实现业务服务：

```text
PC Web / React -----------+
                         |
手机小程序 ---------------+--> Spring Boot / API v1
                                      |
                                      +--> 认证与家庭权限
                                      +--> 物品/分类/位置/批量操作
                                      +--> 统计看板
                                      +--> Excel/CSV 导入
                                      +--> 图片存储
                                      |
                                      +--> MySQL + Flyway
```

建议新增的数据模型：

- `user`：用户身份、昵称、密码摘要和状态。
- `household`：家庭数据空间。
- `household_member`：家庭成员和 OWNER/MEMBER 角色。
- `refresh_token`：可撤销、可轮换的刷新令牌。

现有 `item`、`category`、`location` 增加 `household_id`，所有业务查询必须自动按当前用户家庭过滤，不能信任客户端任意传入的家庭 ID。

统一 API 建议：

```text
/api/v1/auth/*
/api/v1/items/*
/api/v1/categories/*
/api/v1/locations/*
/api/v1/dashboard/*
/api/v1/imports/*
```

PC 端重点承担：

- Excel/CSV 批量录入。
- 批量修改分类和位置。
- 数据清洗、重复项处理。
- 完整统计看板。
- 家庭成员、备份和系统配置。

小程序重点承担：

- 登录和家庭绑定。
- 快速录入物品。
- 拍照上传。
- 搜索、筛选和查看详情。
- 修改、移动和删除。

## 15. v1.6：数据保护与家庭运营

### 15.1 范围与架构决策

用户要求继续实现“数据保护和家庭运营”，并在完成后重新评估整个项目。v1.6 最终范围包括误删保护、审计活动、家庭运行摘要、备份/恢复工具、统计查询优化和 OWNER 运维界面。

- 备份和恢复由服务器侧 PowerShell 工具执行；恢复默认仅验证，实际应用必须写入隔离且为空的目标。

- OWNER 专属接口统一置于 `/api/v1/operations`，MEMBER 无权访问。

### 15.2 后端完成模块

- Flyway V5 为物品增加删除时间和删除操作者，并新增审计事件表及索引。

- OWNER 可分页查看回收站、恢复物品或永久删除；分类/位置被普通或回收站物品引用时禁止删除。
- 记录物品创建、修改、移动、删除、恢复、永久删除、整批录入、成员创建/启停和会话撤销事件。

- 备份状态读取限制文件大小并识别未配置、缺失、无效、过期、未验证和健康状态；拒绝未来时间等异常状态。
- 仪表盘总资产、临期前 20 项、分类分布和位置分布改为数据库聚合/有界查询。
- 分类和位置列表各用一次聚合查询获得物品数量，移除 N+1。
- `/operations/**` 由 Spring Security 限定 OWNER；访问拒绝统一返回 403。

### 15.3 PC Web 完成模块

- 新增 OWNER“家庭运行日志”页面和路由，包含保护状态条、家庭摘要、纵向活动纸带和回收站。
- 活动支持动作筛选与分页；异步请求使用序列号避免旧响应覆盖新筛选结果。

- 保持四 Tab 基础结构，没有把复杂回收站管理强塞入本轮移动端范围。

### 15.5 备份与恢复工具

- `ops/backup.ps1` 打包 MySQL dump 和上传目录，使用 PBKDF2-SHA256 210,000 次派生、AES-256-CBC 加密及 HMAC-SHA256 先加密后认证。
- 归档内清单记录文件大小和 SHA-256；状态 JSON 原子写入且不含口令。
- `ops/restore-backup.ps1` 默认仅验证，并拒绝认证失败、摘要篡改、路径穿越、重复条目和未声明文件。
- 实际恢复要求目标数据库与源库不同，且通过 `information_schema` 确认目标中没有表或存储例程；上传目标必须是新建空目录。
- 没有图片的家庭备份按安全空操作处理；所有临时明文在 `finally` 中清理。
- 子进程不会继承备份口令和数据库密码，降低凭据泄露面。
