# v1.6.0 - Data protection and household operations

Release date: 2026-07-21

## Highlights

- Item deletion is recoverable through a household-scoped recycle bin; OWNER can permanently delete.
- Append-only audit events cover item, batch-entry, member and session-management actions.
- OWNER receives paginated household activity, an operations summary and member-session revocation.
- Dashboard/category/location statistics use bounded database aggregation and exclude deleted items.
- Web adds the household operations tape, recycle-bin recovery and explicit destructive confirmations.
- Mini Program v1.6 adds an OWNER-only protection summary without changing the four-tab navigation; MEMBER never
  requests the protected summary API.
- `ops/backup.ps1` packages MySQL and uploads, signs/encrypts the archive, verifies its round-trip and
  publishes a non-sensitive status JSON. `ops/restore-backup.ps1` defaults to verification and refuses
  source-database overwrite; apply mode requires an isolated database and an empty upload directory.
- CI checks PowerShell syntax, encrypted round-trip, tamper rejection and plaintext cleanup.

## Upgrade notes

1. Use the v1.6 backup script to create and verify an encrypted backup of the current v1.5 data
   before applying Flyway V5. MySQL DDL is not transactionally reversible.
2. Configure `APP_BACKUP_STATUS_PATH` to a status JSON location readable by the backend but outside
   the archive/passphrase locations. Configure staleness with `APP_BACKUP_STALE_AFTER_HOURS`.
3. Schedule `ops/backup.ps1` under a restricted account and keep `BACKUP_PASSPHRASE` in the scheduler
   secret store. See [`../../ops/README.md`](../../ops/README.md).
4. Import `miniapp/` with the production AppID and re-run device checks against the registered HTTPS
   request domain.

## Verification gates

- Backend unit/integration and real MySQL migration/isolation tests.
- Frontend unit, lint, production build, desktop and 375px Playwright flows.
- Mini Program utility tests plus JavaScript/JSON checks.
- PowerShell parsing, encrypted fixture round-trip, verify-only recovery, tamper rejection and cleanup.

Backups remain an operator-owned process. The backend only reads a bounded non-sensitive status file;
it never receives encryption secrets, opens archives or performs a restore.
