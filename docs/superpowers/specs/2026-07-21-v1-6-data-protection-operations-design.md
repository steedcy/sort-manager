# v1.6 数据保护与家庭运营设计

## 1. 目标

让家庭物品数据具备三层保护：日常误删可恢复、重要操作可追溯、服务器故障后备份可验证恢复；同时把 OWNER 日常关心的成员、会话、回收站和系统健康集中到一个清晰的运营入口。

## 2. 版本边界

本版本包含物品软删除/恢复/永久删除、家庭操作历史、成员会话撤销、家庭运营摘要、备份状态、数据库聚合优化、加密备份与恢复验证脚本、CI 和部署文档。不会实现完整版本快照、字段级差异回放、云存储同步、跨家庭迁移、自动执行生产恢复或消息告警平台。

## 3. 后端与数据

- V5 为 `item` 增加 `deleted_at`、`deleted_by_user_id`，新建 `audit_event` 并补充查询索引。
- 所有普通物品查询显式限制 `deleted_at IS NULL`；回收站只查询 `deleted_at IS NOT NULL`。
- 审计写入与业务变更处于同一事务，事务失败不得留下虚假成功日志。
- 运营摘要返回 activeMembers、activeSessions、recycleBinItems、activityLast7Days、latestBackup 和 recentActivity。
- 备份状态文件只允许固定字段和合理大小，路径由 `APP_BACKUP_STATUS_PATH` 配置。

## 4. Web 体验

沿用现有深蓝紫主色与紧凑家庭柜格布局，不采用搜索结果建议的通用企业蓝整套替换。新页面的签名元素是“运行纸带”：左侧连续时间轴像家庭维护标签纸，右侧以动作动词和物品/成员名称形成记录。页面顶部用四个低装饰度状态格显示备份、回收站、成员、近 7 天操作。

- OWNER 从侧栏进入 `/operations`；移动端不增加第六个底部导航项，由看板运营卡进入。
- 回收站与操作历史使用明确标签、服务端分页、空状态和错误恢复。
- “恢复”是主动作，“永久删除”和“撤销全部会话”使用危险色、确认弹窗和请求锁。
- 不使用颜色单独表达状态；所有图标来自 Lucide；触控目标不小于 44px；375px 无横向滚动。

## 5. 备份与恢复

备份包包含数据库 SQL、上传文件、manifest 和校验清单。加密包不与口令存放在同一目录。恢复脚本默认执行认证与内容验证，只有显式 `-Apply` 才写入指定目标数据库；文档要求先恢复到隔离验证库并完成数量/健康检查，再安排生产切换。

## 6. 成功标准

- 删除后普通列表、看板和统计均不可见，回收站可见且恢复后重新出现。
- 跨家庭无法查看或恢复记录，MEMBER 无法永久删除、查看运营日志或撤销他人会话。
- 看板不加载全量物品，分类/位置列表不逐项 count。
- 备份状态不会因文件缺失、过期或 JSON 损坏而显示为健康。
- 后端、Web、小程序、脚本检查、MySQL 联调和 Playwright 全部通过。
