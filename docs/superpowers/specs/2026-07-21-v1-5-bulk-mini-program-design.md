# v1.5 批量录入与小程序基础版设计

## 产品边界

本版本解决两个最高频场景：在 PC 上首次为家庭集中建账，以及家人在手机上随手查找和快速登记。批量录入最多 100 行，整批预检、整批提交；小程序基础版只做登录、总览、查询、快速新增和账号退出。

## Web 交互方向

延续 v1.4 的“家庭柜格索引”语言，不采用设计搜索中偏营销的 Waitlist/Lora 方案。新增的记忆点是“入库托盘”：每一行像待归档标签，左侧有稳定行号，右侧有明确的待检、有效、需修正状态章。色彩继续使用靛蓝/石板，成功状态加入低饱和家庭绿，错误只用于需要修正的格子。

桌面布局：

```text
[批量录入说明 / 下载模板] [粘贴表格] [导入 CSV]
[列映射提示.....................................]
[01 名称 | 数量 | 单价 | 分类 | 位置 | 日期 | 状态]
[02 ...............................................]
[+ 添加一行]                 [预检全部] [确认录入]
```

手机布局将每行折叠为纵向“物品标签卡”，主操作固定在底部导航上方但预留安全区。所有触控目标至少 44px，字段使用可见标签和合适的 `inputMode`，错误紧邻字段并可聚焦。

## API 协议

`POST /api/v1/items/batch` 接收 `{ validateOnly, items }`。响应包含总行数、有效行数、已创建数和逐行结果。任一行无效时提交模式创建数为 0；全部有效时一次保存并返回创建后的物品。分类和位置只能引用当前认证家庭。

## 小程序结构

原生微信小程序使用四个 tab：总览、物品、录入、我的。请求层统一添加 Bearer Token，遇到 401 只执行一次刷新并重放原请求；刷新失败清理本地会话并回到登录页。列表分页每页 20 条，搜索有 300ms 防抖，快速录入仅要求名称和数量，其他字段按需展开。

## 可访问性与性能

Web 保持键盘可用、清晰焦点、减少动态效果和无横向页面滚动。可编辑行拆分为小组件；本地解析上限 100 行，不做虚拟列表。小程序使用原生控件、明确 loading/empty/error 状态和下拉刷新，避免将大图或 Token 写入日志。
