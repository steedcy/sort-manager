# Sort Manager v1.4 家庭账号与安全访问设计

**状态：** 已确认（用户授权自主决策）
**日期：** 2026-07-21
**基线：** v1.3.0 (`bf5f51f`)

## 1. 目标与非目标

v1.4 让当前可用 MVP 能安全部署到个人服务器并由家庭成员访问：提供账号登录、短会话与刷新、成员管理、家庭数据隔离、受保护图片和 PC 端响应式登录体验。

本版本不实现批量导入、小程序客户端、密码自助找回、多个家庭切换、第三方登录或完整容器化；这些留给后续版本。

## 2. 用户流程

1. 首次部署者通过本地环境变量创建 OWNER，并接管默认家庭及全部存量数据。
2. OWNER 登录后可查看既有看板和物品，并创建或禁用家庭成员。
3. 家庭成员登录后只能访问所属家庭的数据，不能进入成员管理。
4. 页面重载时客户端使用一次性 Refresh Token 恢复短 Access Token；退出或刷新重放会吊销会话。

## 3. 后端设计

- Spring Security 无状态资源服务器，HS256 JWT 内含用户 ID、家庭 ID、角色与 token id。
- BCrypt 保存密码；登录失败以规范化用户名和远端地址做内存限流，不信任未经配置的转发头。
- Refresh Token 只保存摘要、token family、过期/撤销/替换信息；刷新在事务与行锁中完成。
- `CurrentHousehold` 从认证主体读取家庭 ID。服务层创建实体时写入家庭，仓库层所有查询显式包含家庭 ID。
- 成员 API 支持列表、创建、启用/禁用；禁止禁用自己与最后一名 OWNER，状态变化撤销该用户刷新令牌。
- 文件上传到 `<upload-root>/<household-id>/`，下载端点按当前家庭解析；文件名为随机 UUID。
- 401、403、429 与业务错误使用统一 JSON；500 只返回通用消息，详细堆栈仅服务端记录。

## 4. 数据迁移

V3 按“建身份表 → 业务表加可空家庭列 → 创建默认家庭 → 回填 → 非空/FK/索引”的顺序执行。分类名称唯一性限定在家庭内。迁移测试覆盖空库和模拟 v1.3 存量库，真实 MySQL 联调覆盖第二次启动幂等性。

## 5. 前端体验与设计系统

### 视觉方向

采用“家庭柜格索引”：登录页由安静的柜格/标签示意与单列登录表单组成，表达房间、位置和物品的关系。延续现有靛青品牌色，以石板灰和暖白作为表面色，绿色仅用于成功状态；不采用重阴影 claymorphism 或通用营销 Hero。

- 正文使用本地系统无衬线字体，中文标题使用系统宋体候选，避免外部字体导致自部署/PWA 离线闪烁。
- 颜色、间距、阴影、圆角和动效通过语义 token 管理。
- Lucide 作为唯一结构图标来源，不用 emoji 充当导航或标题图标。
- 微交互 150–250ms，只使用 opacity/transform，并尊重 `prefers-reduced-motion`。

### 交互约束

- 登录表单使用可见 label、浏览器 autofill、密码显隐、字段内错误、提交 loading 与明确的 401/429 恢复建议。
- 所有主要控件至少 44×44px，移动输入字号至少 16px；焦点环清晰，页面允许缩放。
- 桌面使用侧栏，375px 手机使用最多五项的底部导航并预留 safe-area。
- OWNER 在成员页使用桌面表格/移动卡片；角色不仅靠颜色表达。
- 路由恢复期间显示稳定加载状态，不能闪现受保护内容；路由变化聚焦主内容。

## 6. 客户端会话

`AuthProvider` 负责初始化、登录、刷新、退出和用户状态。Axios 请求拦截器注入 Bearer；响应 401 时使用单飞 Promise 刷新并只重试一次，刷新请求使用独立客户端以避免递归。角色门禁仅改善 UX，真正权限仍由后端强制。

## 7. 成功标准

- 两个家庭可以拥有同名分类，但不能互相读取、修改、删除或关联数据。
- 未登录无法访问业务及图片；OWNER/MEMBER 权限边界正确。
- Refresh Token 原文不入库，轮换后旧 Token 不可再次使用。
- PC 在桌面和 375px 视口完成登录、会话恢复、退出、成员管理和物品 CRUD。
- 本地密钥、初始密码、测试产物和用户未跟踪素材不进入 Git。
