# ADR 0002：v1.4 采用家庭边界的账号与令牌认证

- 状态：Accepted
- 日期：2026-07-21
- 取代范围：ADR 0001 中“暂不引入账号鉴权”的版本边界

## 背景

项目将部署在个人服务器上，由用户与家人通过 PC 和后续小程序共同管理家庭物品。v1.3 的业务 API 和上传文件尚无身份认证，分类、位置、物品及看板查询也没有家庭数据边界，因此不适合直接暴露到家庭网络之外。

用户已明确授权按既定 v1.4 路线自主实现；本 ADR 记录该架构决策及安全边界。

## 方案比较

1. 单一共享密码：实现最少，但无法识别家庭成员、吊销单个成员或扩展小程序访问。
2. 应用内家庭账号 + JWT 短访问令牌 + 可轮换刷新令牌：满足 PC/小程序统一 API，复杂度与家庭规模匹配。
3. 外部身份提供商：安全能力完整，但增加第三方依赖、运维和个人服务器部署成本。

选择方案 2。

## 决策

1. 新增 `app_user`、`household`、`household_member` 与 `refresh_token`；用户可作为 OWNER 或 MEMBER 加入家庭。
2. Access Token 使用 HS256 JWT，默认 15 分钟；签名密钥只从环境变量读取且至少 32 字节。Refresh Token 使用 256 位随机值，数据库仅保存 SHA-256 摘要，刷新时单次使用并轮换。
3. PC 与未来小程序共用 JSON Token 协议。PC 将 access token 放 `sessionStorage`、refresh token 放 `localStorage`；这是兼容小程序的折中，配合短 access 生命周期、刷新轮换、严格 CSP、依赖审计和退出吊销降低 XSS 风险。未来可按客户端类型增加 HttpOnly Cookie 模式。
4. 所有业务表增加非空 `household_id`。家庭 ID 只能从认证主体获得，客户端不能指定；列表、详情、写入、删除、关联对象验证、统计与分页均必须显式按家庭过滤，越权 ID 统一按不存在处理。
5. V3 迁移创建“默认家庭”并回填 v1.3 存量数据，再添加非空约束和索引；V4 对齐真实 MySQL 与 Hibernate 的令牌列类型。分类唯一键由全局名称改为 `(household_id, name)`。MySQL DDL 不承诺事务回滚，上线前必须备份并以恢复备份作为回退方式。
6. 首个 OWNER 仅在无用户时通过 `APP_BOOTSTRAP_*` 环境变量创建；仓库、迁移和日志不得包含初始明文密码。
7. API 进入 `/api/v1`。仅登录、刷新与健康检查公开；业务 API 必须认证，成员管理必须为 OWNER。
8. 上传文件按家庭目录存储，通过认证的 `/api/v1/files/{filename}` 读取；不再暴露公共 `/uploads/**` 静态目录。
9. 生产部署要求 HTTPS 反向代理、显式 CORS 白名单、非 root 数据库账号；服务端错误响应不返回内部异常细节。

## 结果

- 可以独立创建、禁用家庭成员并撤销其会话。
- 家庭隔离需要贯穿每个仓库查询，新增业务查询必须包含家庭边界测试。
- 浏览器端 Token 仍要求严控 XSS；小程序正式接入时需复核客户端安全存储。
- v1.3 客户端不能直接调用 `/api`，升级时必须同步前后端。
- 图片由鉴权 API 返回，前端需使用带 Bearer 的 Blob 加载组件。

## 验证门禁

- Flyway 空库与 v1.3 存量升级测试通过，并在真实 MySQL 上验证回填和约束。
- 未认证访问为 401，MEMBER 访问成员管理为 403，跨家庭资源为 404。
- 登录限流、刷新轮换、过期/撤销/重放、禁用用户均有测试。
- PC 登录、会话恢复、退出、OWNER 成员管理与既有物品流程通过 Playwright。
- `npm audit`、后端测试/打包、前端 lint/build 和代码审查无未解决的高优先级问题。
