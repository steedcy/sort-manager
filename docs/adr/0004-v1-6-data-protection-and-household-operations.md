# 0004 - v1.6 数据保护与家庭运营

**状态：** Accepted
**日期：** 2026-07-21
**规格：** `docs/superpowers/specs/2026-07-21-v1-6-data-protection-operations-design.md`

## 背景

v1.5 已具备家庭账号、Web/小程序访问和批量录入，但删除仍是物理删除，关键操作不可追溯，仪表盘会加载全部物品并在分类、位置统计中逐项查询。个人服务器还缺少可重复的加密备份与恢复验证流程。家庭应用最常见的数据风险不是多租户规模，而是误删、账号会话失控、磁盘或升级故障后无法确认备份可恢复。

## 方案比较

1. **仅做服务器备份：** 实现简单，但无法处理日常误删，也不能解释“谁在什么时候改了什么”。
2. **完整事件溯源：** 可以重建任意状态，但会重写现有 CRUD、迁移和查询模型，复杂度不适合两三人的家庭应用。
3. **软删除 + 操作日志 + 加密备份（采用）：** 保留现有关系模型，用回收站处理误删，用追加式日志提供追溯，用运维脚本覆盖灾难恢复。

## 决策

1. 物品删除改为家庭范围内的软删除。普通查询、统计、分类和位置计数必须排除已删除物品；回收站提供分页查看与恢复；只有 OWNER 可以永久删除。
2. 新建追加式 `audit_event` 表，记录家庭、操作者、动作、实体类型/ID/名称、摘要和时间。记录物品创建、修改、移动、删除、恢复、永久删除、批量录入，以及成员创建、启停和会话撤销。客户端不能写入或修改日志。
3. 新增 OWNER 家庭运营 API，提供近 7 天操作数、回收站数量、启用成员数、活动会话数、最近操作和备份状态；活动历史支持服务端分页与动作筛选。
4. 成员禁用继续立即撤销全部刷新令牌；OWNER 另可在不禁用账号的情况下撤销指定成员全部会话。该动作写入审计日志。
5. 仪表盘资产总值、临期/过期数量、分类与位置统计改为数据库聚合或有界查询，禁止加载全量物品计算，也禁止逐分类/逐位置计数。
6. `ops/backup.ps1` 生成 MySQL dump 与上传目录清单，压缩后使用 PBKDF2 + AES-256-CBC + HMAC-SHA256 加密；明文临时文件必须在 finally 中清理。`ops/restore-backup.ps1` 必须先校验 HMAC、归档哈希和文件清单，默认只验证，实际恢复要求显式 `-Apply` 和独立目标数据库。
7. 后端只读取配置路径中的非敏感备份状态 JSON，不接触备份口令、不执行数据库恢复，也不向浏览器返回文件路径或密钥。
8. Web 端新增 OWNER 专属“家庭运行日志”。视觉继续沿用家庭柜格索引，签名元素为纵向“运行纸带”：时间、操作者、动作和对象形成可扫描的家庭维护记录；危险操作采用可见文本、二次确认和 loading 锁。

## 后果

- 删除物品不再立即释放数据库空间和图片文件，需要定期由 OWNER 清理回收站。
- 审计日志只记录必要摘要，不保存密码、Token、完整请求体或物品描述，降低敏感数据扩散。
- 备份状态取决于外部计划任务按约定写入状态文件；应用不能把“脚本存在”误报为“备份成功”。
- V5 迁移需要在升级前备份；MySQL DDL 失败仍必须通过备份恢复。

## 验收门禁

- 真实数据库测试证明软删除不可见、家庭隔离、恢复可见、永久删除受 OWNER 限制。
- Repository 查询计数或行为测试证明看板、分类和位置统计不再出现 N+1/全量加载。
- 会话撤销测试证明目标成员的现有 refresh token 立即失效。
- PowerShell 解析检查与加密往返测试证明篡改备份会被拒绝，验证模式不修改数据库。
- Web 在桌面和 375px 视口完成运营日志、筛选、恢复和会话撤销流程。
